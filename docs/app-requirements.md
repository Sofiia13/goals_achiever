# Вимоги до застосунку Goals Achiever

## 1. Опис проєкту

Goals Achiever — це вебзастосунок для планування та досягнення особистих цілей. Його основна мета — допомогти користувачам організовувати свій час, розділяти великі цілі на менші завдання та відстежувати власний прогрес.

Застосунок використовує штучний інтелект для формування плану досягнення цілі, а також елементи гейміфікації для мотивації користувачів. За виконання завдань користувачі отримують бали, підтримують серії активності та відкривають досягнення.

## 2. Функціональні вимоги

1. **Керування обліковим записом.** Користувач повинен мати можливість зареєструватися, увійти в систему та вийти зі свого облікового запису.

2. **Керування цілями.** Користувач повинен мати можливість створювати, переглядати, редагувати та видаляти особисті цілі.

3. **Параметри цілі.** Для кожної цілі користувач повинен мати можливість вказати назву, опис, кінцевий термін і бажаний результат.

4. **AI-планування.** Застосунок повинен використовувати зовнішній AI API для автоматичного поділу цілі на менші завдання з рекомендованими термінами виконання.

5. **Керування завданнями.** Користувач повинен мати можливість переглядати список завдань, змінювати їх статуси та позначати завдання як виконані.

6. **Гейміфікація.** Система повинна нараховувати бали за виконані завдання, відстежувати серії активності та надавати досягнення за визначені результати.

7. **Аналітика прогресу.** Застосунок повинен відображати статистику виконання завдань і досягнення цілей за день, тиждень та місяць.

8. **Адаптація плану.** Якщо користувач не виконує завдання вчасно, система повинна дозволяти коригувати майбутній план з урахуванням поточного прогресу.

9. **Адаптивний інтерфейс.** Основні функції застосунку повинні бути доступними як на комп'ютерах, так і на мобільних пристроях.

## 3. Нефункціональні вимоги

* **Зручність використання:** інтерфейс повинен бути зрозумілим і послідовним.
* **Продуктивність:** основні операції з цілями та завданнями повинні виконуватися без помітних затримок за нормальних умов роботи.
* **Безпека:** дані користувачів повинні бути захищені від несанкціонованого доступу.
* **Надійність:** помилки мережі або недоступність AI API не повинні призводити до втрати вже збережених даних.
* **Підтримуваність:** код повинен мати зрозумілу структуру та бути придатним до тестування й розширення.
* **Сумісність:** застосунок повинен коректно працювати в сучасних браузерах.
* **Вартість:** під час розробки слід надавати перевагу безкоштовним інструментам і сервісам або їхнім безкоштовним тарифам.

## 4. Технологічний стек

* **Frontend:** React 19, TypeScript, Vite, React Router, Axios.
* **3D-візуалізація:** Three.js, React Three Fiber, drei (дорожня карта прогресу).
* **Стилізація:** SCSS (CSS Modules).
* **Backend:** Node.js, Express 5, TypeScript.
* **База даних:** PostgreSQL, Prisma ORM.
* **Автентифікація:** JWT (access + refresh токени), bcryptjs.
* **AI:** Google Gemini API (безкоштовний тариф) для формування та коригування планів.
* **Тестування:** Vitest, React Testing Library, Supertest (планується).
* **Якість коду:** ESLint, перевірка типів TypeScript.
* **Контроль версій і CI:** Git, GitHub, GitHub Actions.
* **Розгортання:** Vercel (frontend), безкоштовний хостинг для backend і БД (Render / Neon / Supabase).

## 5. Вибір агентної IDE

Для роботи протягом курсу обрано **Visual Studio Code з розширенням Claude Code**.

Обґрунтування:

* **Повноцінний агентний режим.** Claude Code читає й редагує файли, запускає команди в терміналі (тести, lint, збірку, git) і виконує багатокрокові задачі, а не лише доповнює код.
* **Налаштовуваний harness.** Підтримуються файл контексту `CLAUDE.md`, правила дозволів (allow / ask / deny) у `.claude/settings.json`, хуки до та після дій агента, власні команди (skills) і MCP-сервери. Це покриває всі елементи harness, які розроблятимуться в наступних практичних роботах.
* **Інтеграція з GitHub.** Агент працює з історією комітів, гілками та pull request через `git` і `gh` CLI.
* **Знайоме середовище.** VS Code уже використовується для розробки проєкту, тож перехід не потребує зміни робочого процесу.
* **Вартість.** VS Code безкоштовний; Claude Code доступний за студентською / базовою підпискою.

Альтернативи, які розглядалися: Cursor (зручний, але harness менш прозорий і обмеження безкоштовного тарифу) та GitHub Copilot у VS Code (агентний режим слабше налаштовується через хуки й правила дозволів).

## 6. Обмеження проєкту

Проєкт призначений для індивідуального планування особистих цілей. Основна увага приділяється керуванню цілями та завданнями, AI-плануванню, гейміфікації й аналізу прогресу.

Навчання власної AI-моделі не передбачається. Для генерації планів використовуватиметься зовнішній AI API. Фактичний набір функцій залежатиме від доступності необхідних сервісів та їхніх безкоштовних тарифів.

## 7. Критерії успіху

Проєкт вважається успішним, якщо:

* користувач може створювати та редагувати цілі;
* AI може сформувати перелік завдань для досягнення цілі;
* користувач може відзначати виконані завдання;
* система правильно оновлює бали та статистику;
* користувач може переглядати власний прогрес;
* основні сценарії роботи перевіряються автоматизованими тестами;
* застосунок можна запустити відповідно до інструкцій у README.md.
